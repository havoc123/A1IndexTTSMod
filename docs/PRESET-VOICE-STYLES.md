# 基础问候语与话题开场白情感库

数据版本：2026-10-08.1，随插件 v0.7.6 正式接入。中文数据以 UTF-8 保存，中文内容直接可读。

## 内容与范围

根据本机游戏数据中的角色说话风格、性格描述、话题背景与台词，为实际存在的基础问候语和话题开场白编写演绎配置。情绪是离线编写的表达建议，并非游戏原有的情绪字段。

| 项目 | 数量 |
| --- | ---: |
| 基础问候语 | 3373 |
| 话题开场白原始条目 | 781 |
| 从条件模板中拆出的分支台词 | 26 |
| 总记录数 | 4180 |
| 覆盖角色 | 1232 |

总数包含条件模板及其分支，因此不等于 4180 句互不重复的台词。同一句通用问候语会按不同角色分别保存，并结合角色口吻生成表达。缺少人物卡和性格信息的角色使用中性表达，不编造角色背景。没有开场白的角色不新增台词。

每条配置包含角色名、角色 ID、来源、原台词、文本指纹及 `voice_style`：

- `emotion_tags`：中文情绪标签。
- `delivery`：中文说话方式，包括角色口吻、语速、重音或句尾表达。
- `intensity`：0 至 1 的表达强度。

例如，念乔的“上回那松子糖，你说甜，我可记着呢。今日若有得吃，还要不要？”配置为：

```json
{
  "emotion_tags": ["愉悦", "关切"],
  "delivery": "清亮俏皮，带浅浅笑意；“我可记着呢”稍作强调，末尾轻快询问，保持日常交谈感。",
  "intensity": 0.35
}
```

## 文件

- `config/preset-voice-styles.zh-CN.json`：展开后的完整数据，构建时内置到插件 DLL。
- `config/preset-voice-styles.authoring.json`：逐句演绎选择、角色口吻配置和个别台词的单独配置。
- `scripts/Generate-PresetVoiceStyles.py`：将上述编写结果与游戏表格组合，生成完整库；不调用模型，不依靠关键词猜测情绪。

来源为 `tbnpcbasecfg.json`、`tbnpctopicchat.json` 和 `tbnpcaipersona.json`。数据包不包含这些游戏原始表格。库中记录来源指纹，便于区分游戏数据版本。

## 接入约定

**情感库已接入插件，构建时内置到 DLL，默认启用，无需另装数据文件。** `[Stage3Mvp] PresetVoiceStyles = true` 控制此功能；已有配置缺少该项时也使用默认启用值。修改仓库中的 JSON 后需要重新构建插件。

运行时遵循以下规则：

1. 当前回复已有有效情感或说话方式时，优先使用当前回复的数据。
2. 按当前角色 ID 与实际台词精确匹配，仅忽略首尾空白；可读取当前话题 ID 时，用它区分相同文本在不同话题中的配置。无法区分且演绎有冲突时不匹配。
3. 不借用其他角色的配置，不继承上一轮回复的情感。实际台词被改写且无法匹配时，保留明确的未匹配状态。
4. `speech_policy: speak` 表示可作为人类台词使用。
5. `speech_policy: template_only` 表示含剧情条件的原始模板，仅作来源记录，不能直接朗读；应匹配实际选中的 `topic_opening_branch`。
6. `speech_policy: nonhuman_or_narration` 表示动物叫声、纯动作描写、省略号或游戏标记为宠物的记录，不按普通人类台词自动合成。
7. 第三页诊断展示中文标签、说话方式、强度及“离线预设库”来源，附带匹配条目和库版本；纯文本预设台词不沿用上一轮的模型请求信息，也不伪造原始回包。

普通聊天的 `AddNpcChatMessage` 入口允许精确匹配的纯文本预设台词进入现有合成流程，复用自动朗读、参考音选择、音量、取消和消息时间戳去重机制。普通结构化回复及说服回复缺少有效风格时也可按相同规则匹配。未命中的纯文本消息继续跳过。CosyVoice 的最终 instruction 使用匹配的语音风格。

此库不会强制游戏显示开场白，也不会改变开场白的出现条件。

## 再次生成

在项目根目录执行：

```powershell
python scripts/Generate-PresetVoiceStyles.py --tables "包含三个来源 JSON 的目录"
```

不指定 `--tables` 时，使用 `.state/prompt-analysis-20261008`。脚本会检查来源文件指纹；游戏表格更新后，需要先重新整理演绎选择，不能直接把旧的顺序索引套到新表格上。
