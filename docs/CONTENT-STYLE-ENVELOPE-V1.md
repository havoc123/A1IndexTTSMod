# NPC 正文语音风格帧 v1

当插件语音功能和提示增强开启时，只要有可朗读台词，模型必须在游戏回复 JSON 的 `content` 字符串内部末尾追加且仅追加一帧：

```text
你来了。<a1tts_v1>{"emotion_tags":["克制的关切"],"delivery":"声音放轻，语速稍缓","intensity":0.3}</a1tts_v1>
```

帧内必须是普通 JSON 对象，且只含 `emotion_tags`、`delivery`、`intensity` 三项。标签需为 1–3 个非空字符串（每项最多 16 字），`delivery` 为 1–80 字，`intensity` 为 0–1 的有限数。最大帧长为 2048 个字符。解析器接受帧内一个标准 JSON Markdown 围栏作为容错，但提示始终要求输出无围栏 JSON。情绪平淡或上下文不足时，由同次模型响应生成平静、中性的表达，不推测隐藏情绪；只有没有可朗读台词时才省略帧，不使用 `null` 帧。插件不会自行补造缺失风格。

帧是外层 `content` 字符串的一部分，帧内双引号、反斜杠和换行必须按外层 JSON 字符串规则转义。不得将帧放在 `content` 外或整个回复 JSON 后面。提示明确将帧视为可见正文之外的传输元数据例外，其他游戏字段与数值规则不变；历史无帧回复与旧顶层 `voice_style` 示例不替代本轮格式要求。完整输出示例由 JSON 序列化器生成，保持中文和标记可读并正确转义字符串。

请求增强覆盖有 Schema 和无 Schema 两条路线。有 `ResponseFormat` 时同步增强其 `content.description`；游戏自定义模型路线的 `ResponseFormat` 为空时，只增强现有文本输出契约、尾部提示与 JSON 示例，保留原请求选项，不凭空添加供应商 Schema。第三页会说明本轮没有 Schema，并显示中文文本契约增补；增强失败会显示实际失败阶段。

从 v0.7.5 起，字段说明、Schema 描述和文本契约增补共用同一份必填规则。第三页及复制摘要记录 `VoiceStyleRequired`；要求已添加且有可朗读台词、但响应无风格时，显示“已要求返回语音风格，但在本 Mod 收到的响应中未检测到”，不将该状态直接归因为模型漏生成或代理清洗。

模型只生成结构化文本，不计算 Base64、摘要或校验和。协议标记与 JSON 在 `content` 中传输，不新增游戏回复对象的字段。插件在 NPC 回复映射、显示、历史记录和下轮提示之前解包并移除帧；TTS 收到的是清洁正文，风格保存在插件自己的轮次记录与 TTS 请求快照中。

若响应同时包含历史兼容字段 `voice_style` 和正文帧：合法的顶层 `voice_style` 优先；其缺失、为 `null` 或无效时使用合法正文帧。无论来源如何，插件都会从交给游戏的 JSON 中移除顶层 `voice_style`。正文帧优先满足跨代理和未知字段白名单重建的兼容目标。

只有完整、唯一且位于正文末尾的风格 JSON 可产生风格。解析器兼容模型误用 `</a1tts_v1>` 作为起始标记的情况：该标记后必须紧跟 JSON 对象，首项为 emotion_tags、delivery 或 intensity；从实际存在的对象中恢复帧边界，再执行原有三字段、值范围、最大长度、唯一帧和末尾位置检查。允许这类 JSON 后缺少结束标记，以及帧内单个标准 JSON Markdown 围栏；不补造任何风格字段。重复帧、超长帧、帧后有文字、无效 JSON/字段和未完成的元数据不会产生风格；可识别的协议帧会从游戏正文移除，真实尾随对白保留，并把无效状态与原因显示在“本轮数据”。损坏的外层 JSON 不猜测、不修复。孤立结束标记、其后无关的 JSON、未知协议版本及普通正文原样保留。协议标记本身是保留文本，模型不应在正常对白中引用它。

实现只能恢复在我方观察边界仍存在的数据。模型漏帧、上游响应 Schema 限制，或游戏/代理在回复到达该边界前移除/改写正文，都不能由插件还原。正文帧会增加响应长度；部分第三方代理会根据 `content` 推断游戏 `emotion`，其中的中文标签可能轻微影响该推断。插件不改动第三方 MOD，也不覆盖原游戏 `emotion`。提示增强默认开启但受总语音开关控制；需要避免第三方 emotion 推断读取帧文字时，可关闭 `Stage3Mvp.PromptEnhancement`，此时不承诺风格传输。
